# 二次元动画创作与独立 Live2D 资产库需求方案

- 产品：Cimora Studio
- 文档版本：v1.0
- 日期：2026-10-13
- 文档用途：产品、设计与技术评审，作为功能拆分和验收依据
- 状态：产品方向已确认；技术可行性、质量阈值和排期待评审

## 1. 背景与目标

现有无限画布已具备文字、图片节点、连线、分组、AI 生图、参考图生图、视频生成和素材保存等基础能力，但缺少面向二次元制作的业务组织方式。

本期优先服务个人创作者，兼顾小型工作室，同期交付两条独立功能线：

1. **动画短片创作**：通过项目级 Agent、分类创作页面、资产联动和基础剪辑，在产品内完成动画短片并导出。
2. **独立 Live2D 资产库**：用户通过专用界面，将 PNG 立绘制作成基础 Live2D 模型，管理模型资产并导出至其他软件使用。

现状以产品负责人在需求讨论中提供的信息为准。本文不是对当前仓库或生产环境的功能审计，技术团队需核对实际接入点。

## 2. 已确认的产品边界

| 事项 | 结论 |
| --- | --- |
| 优先用户 | 个人创作者；兼顾小型工作室 |
| 创作页面 | 一个项目包含多个独立页面，各创作页面保留自己的画布；剪辑使用时间线 |
| 动画资产 | 分为“我的资产”和“项目资产”，支持引用和版本联动 |
| 资产更新 | 提示新版本，用户选择应用范围；不自动覆盖已有产物 |
| 剧本入口 | 故事想法与已有剧本两种入口，均通过 Agent 对话承接 |
| Agent | 项目级助手，结合当前页面和选中对象工作 |
| 短片音频 | 使用视频生成模型自带音频，不单独建设 TTS 配音流程 |
| 多角色 | 必须覆盖多角色同框、对白交替 |
| Live2D | 独立资产库及专用制作界面，不进入项目画布，不由 Agent 操作 |
| Live2D 质量定位 | 自动生成基础模型、有限修正，精细制作留给外部工具 |
| 交付安排 | 动画短片闭环与 Live2D 同期交付，分别验收 |

### 2.1 Live2D 独立性要求

- Live2D 资产库有独立入口，不属于某一个动画项目。
- 不在 OC、场景、剧本、分镜画布中创建 Live2D 节点或制作任务。
- 项目 Agent 不读取、创建、修改或调度 Live2D 资产与任务。
- Live2D 模型不进入动画“我的资产／项目资产”的引用与版本更新链路。
- 一期通过专用界面上传 PNG 创建模型；不做 OC 资产一键转 Live2D 的跨模块联动。
- 用户可以将已有立绘文件手动上传至 Live2D 模块，不自动建立与原 OC 的关联。
- Live2D 内部可使用自动拆层与绑定算法，但交互方式是专用页面中的按钮、表单和预览，不是 Agent 对话。

## 4. 动画资产库

### 4.1 我的资产与项目资产

| 类型 | 用途 | 主要内容 |
| --- | --- | --- |
| 我的资产 | 跨项目复用个人素材 | 角色、场景、图片、视频、音频等 |
| 项目资产 | 保存当前作品采用的素材和版本 | 项目角色、场景、参考素材及选定产物 |

基础功能包括资产浏览、按名称搜索、按类型筛选、详情查看、引用和版本选择。

画布中的探索结果不要求全部转为正式资产。用户或获得明确指令的 Agent 可将选定结果保存到资产库。

### 4.2 引用与版本规则

以下作为本期建议实现规则，进入技术评审：

1. 从“我的资产”引入项目时，形成项目版本并记录来源。
2. 项目内调整不自动改变“我的资产”，也不影响其他项目。
3. 用户可主动将项目版本保存回“我的资产”，形成新版本。
4. 剧本、分镜和生成任务记录所引用的资产及版本。
5. 资产出现新版本后，提示受影响对象，由用户选择应用范围。
6. 应用新版本更新后续生成参考，不重写已生成图片或视频。
7. 重新生成须单独发起；原结果保留为候选版本。

“引用资产”表示带入设定与参考素材，不表示系统已经保证生成结果中的角色或场景一致性。

## 5. 动画创作页面

### 5.1 OC 设计

- 创建、编辑角色名称、外观、性格和背景设定。
- 上传或生成角色参考图，复用已有生图能力。
- 管理服装、表情等参考版本。
- 从候选结果中选定标准立绘和参考素材。
- 保存为项目资产，或主动保存到“我的资产”。

产物：角色档案、标准立绘、参考素材及版本信息。

### 5.2 场景设计

- 创建、编辑地点、环境、时间、天气和画面风格。
- 上传或生成场景图。
- 管理不同视角、昼夜和天气状态。
- 选定参考图并保存为场景资产。

产物：场景档案、参考图及状态版本。

### 5.3 剧本设计

两种输入均由 Agent 对话实现：

1. 用户描述故事想法，Agent 辅助生成大纲、分场和对白。
2. 用户上传或粘贴已有剧本，Agent 识别场次、角色、场景和对白。

功能要求：

- 输出可编辑的结构化结果，不只在聊天中回复文本。
- 场次可关联项目角色和场景。
- 未匹配到的角色或场景需要明确标识，不静默引用无关资产。
- 用户可直接修改剧本，Agent 后续操作以当前保存内容为准。
- 不强制用户从大纲开始；已有剧本可直接进入分镜设计。

### 5.4 分镜与镜头制作

每个镜头至少包含：

| 字段 | 说明 |
| --- | --- |
| 镜头编号、顺序、所属场次 | 组织镜头和装配成片 |
| 画面描述 | 人物动作、构图和叙事内容 |
| 角色与场景引用 | 明确参考资产及版本 |
| 景别、运镜要求 | 用户可编辑的镜头要求 |
| 预期时长 | 生成与剪辑参考，实际受模型能力约束 |
| 对白 | 说话角色、文本及先后顺序 |
| 参考图与生成结果 | 保留候选版本和当前选定版本 |
| 制作状态 | 草稿、待生成、生成中、成功、失败等 |

用户可逐镜生成或确认方案后批量生成。单镜头失败可以独立重试，不需要重新执行整个项目。

## 6. 项目 Agent

### 6.1 工作范围

- 读取动画项目内容、资产、当前页面及选中对象。
- 创建和修改角色、场景、剧本和分镜。
- 引用现有资产，发起图片和视频生成任务。
- 将结果放入对应页面，说明操作对象与修改结果。
- 按分镜顺序装配初版时间线，用户可继续手动调整。
- 跨页面保留项目对话和任务状态。

明确排除 Live2D 资产库、模型文件及其制作任务。

### 6.2 确认机制

| 操作 | 行为 |
| --- | --- |
| 新建草稿、整理素材 | 可直接执行 |
| 修改用户明确指定的内容 | 在指令范围内直接执行 |
| 批量生成图片、视频 | 先确认故事／分镜方案；已明确授权的批次直接执行 |
| 覆盖其他已确认内容 | 展示对象和影响范围，确认后执行 |
| 应用资产新版本 | 用户选择影响范围后执行 |

用户明确授权“一次生成全部镜头”后，不逐镜重复询问。任务状态须区分执行中、成功和失败，不能仅凭 Agent 的文字回复判断完成。

## 7. 原声音频与成片剪辑

### 7.1 模型原声音频

- 使用视频生成模型随视频返回的音频。
- 生成请求传递角色、对白文本和说话顺序，具体适配由技术确认。
- 必须覆盖同一镜头中多个角色出现、交替说话，以及多镜头对白衔接。
- 生成结果可试听；对白不符、串角色或音画异常时，用户可重新生成镜头。
- 不单独增加预设音色选择、声音克隆或 TTS 配音流程。

如果模型只提供混合音轨，只承诺整个镜头的原声控制，不承诺单独调整某个角色的声音。

### 7.2 基础时间线

一期采用一个成片时间线，支持：

- 导入项目中选定的镜头结果。
- 镜头排序、移动、裁剪和替换版本。
- 镜头原声音频与视频同步移动、裁剪。
- 镜头原声的音量调整和静音。
- 添加背景音乐，调整位置、长度和音量。
- 根据实际音频生成字幕，允许编辑文字和时间。
- 预览成片，导出视频文件。

字幕以生成音频为校对依据，剧本对白只作为参考，不默认实际音频逐字符合剧本。导出格式、分辨率、帧率、最大时长等限制在技术评审后补齐。

## 8. 独立 Live2D 资产库

### 8.1 模型资产管理

- 用户无需创建或打开动画项目，即可进入 Live2D 资产库。
- 通过“新建模型”上传 PNG 立绘并命名。
- 列表展示封面、名称、更新时间和当前制作状态。
- 支持按名称搜索、按状态筛选、进入详情及下载已生成模型包。
- 模型详情保存源图、图层修正、绑定设置、预览结果与导出记录。
- 关闭详情后再次进入，可继续未完成制作，不要求重新上传或从头执行。
- 重新生成时保留上一份成功结果，便于对比和重新下载。

一期必需入口是上传 PNG。导入外部现成模型、模型交易与公开社区不纳入本期。

### 8.2 制作流程

```text
独立资产库 → 新建模型并上传 PNG → 自动拆层
→ 用户检查／有限修正 → 自动绑定
→ 参数调整与动作预览 → 导出并保存在资产库
```

所有步骤在专用制作界面完成，不使用画布节点、项目 Agent 或对话指令。

| 阶段 | 用户能力 | 系统反馈 |
| --- | --- | --- |
| 上传 | 选择源图、设置名称 | 校验格式及技术确认后的尺寸限制 |
| 拆层 | 发起拆层、查看结果 | 显示处理中、成功或失败状态 |
| 修正 | 查看和隐藏图层、修正部件类型、上传替换图层 | 显示合成预览；需重新绑定时明确提示 |
| 绑定 | 发起自动绑定 | 显示绑定结果和失败原因 |
| 调整 | 调整眨眼、张嘴、头部转动幅度 | 实时或按技术方案更新预览 |
| 预览 | 播放基础测试动作 | 检查破图、错位与遮挡 |
| 导出 | 生成和下载模型包 | 显示导出状态、文件信息与失败原因 |

隐藏图层的界面需要区分“临时预览隐藏”和“参与模型输出的启用状态”，避免误操作导致导出缺部件。

### 8.3 导出要求

- 目标为可供外部软件加载的标准 Live2D 运行模型包。
- 基础文件包括 `.model3.json`、`.moc3`、纹理贴图，以及实际需要的物理、表情等附属文件。
- 文件引用、相对路径和依赖完整，下载后无需用户手工补齐文件。
- 以技术评审确定的目标软件及版本验证兼容性，优先验证 VTube Studio。
- `.cmo3` 可编辑工程是否能够稳定导出，列为技术验证项，不作为当前已承诺能力。
- 若无法交付可编辑工程，产品说明须准确描述外部精修路径，不把运行模型包宣传为可直接编辑的工程。

### 8.4 质量定位与异常处理

- 定位为基础模型生成，不承诺任意 PNG 一键达到专业定制质量。
- 技术验证后明确支持的画风、姿态、遮挡程度和图像要求，并展示在上传入口。
- 拆层、绑定和导出失败分别显示原因，允许修正后重试对应阶段。
- 缺少关键部件或不支持的输入，应明确提示，不能将无效文件标记为制作成功。
- 调整图层使旧绑定失效时，提示重新绑定；调整参数使旧导出过期时，提示重新导出。

## 9. 技术验证任务与上线门槛

| 验证项 | 需要给出的结论 |
| --- | --- |
| 自动拆层 | 支持输入范围、常见失败类型、需要人工修正的内容 |
| 自动绑定 | 中立姿态还原、眨眼、张嘴、转头表现及局限 |
| Live2D 文件导出 | 真实文件可加载性、完整性、目标软件兼容性 |
| 可编辑工程 | 是否支持稳定导出 `.cmo3`，外部精修如何衔接 |
| 多角色带音频视频 | 对白内容、说话顺序、人物对应关系和口型同步效果 |
| 跨镜头表现 | 角色视觉一致性与音色一致性的可达到水平 |
| 字幕 | 实际音频的转写准确性、时间对齐与人工修正方式 |
| 成片处理 | 不同镜头规格统一、音画同步、导出可靠性 |
| 部署与成本 | 依赖授权、算力、平均耗时、失败重试成本及容量限制 |

技术团队应提交真实输入、生成产物、失败样例、目标软件测试结果及建议支持范围。第三方项目 README 或文件扩展名不能替代验收证据。

候选技术仅供验证，不构成选型承诺：

- [See-through](https://github.com/shitagaki-lab/see-through)：图片拆层候选。
- [PSD2Live](https://github.com/tsunehimatoi/psd2live)：分层素材自动绑定与导出候选。

多角色原声视频与 PNG 转 Live2D 是本期核心风险，应先验证，再确定对外质量承诺。若关键能力未达标，应提交范围调整评审，不能静默用视频动画或其他自研格式替代标准 Live2D 导出。

## 10. 验收场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 从想法创作短片 | Agent 将想法转成可编辑剧本、分镜，关联资产并生成镜头，最终可剪辑导出 |
| A02 | 导入已有剧本 | 上传或粘贴后可识别结构，用户可修正并直接进入分镜阶段 |
| A03 | 资产跨项目复用 | 角色可引入不同项目；某项目修改不自动影响其他项目 |
| A04 | 选择性应用资产更新 | 三个镜头引用同一角色，仅对选中的两个应用新版本；旧视频不被覆盖 |
| A05 | 多角色对白 | 验收样例至少包含两个角色同框且交替说话，检查台词、顺序、角色对应与音画表现 |
| A06 | 剪辑与字幕 | 排序、裁剪、音量、字幕调整可保存；导出可播放，裁剪后音画同步 |
| A07 | 单任务失败 | 单镜头失败可独立重试，其他成功结果保留 |
| A08 | Agent 确认机制 | 批量生成和扩大覆盖范围前按规则确认，授权后不逐项重复询问 |
| L01 | 独立入口 | 不打开动画项目、不启动 Agent、不进入画布，也能完成模型制作 |
| L02 | 模型继续制作 | 从资产库重新打开模型，源图、修正和制作状态可恢复 |
| L03 | 图层有限修正 | 可检查图层、纠正部件类型、替换图层并重新绑定 |
| L04 | 基础动作 | 在预览及目标软件中验证眨眼、张嘴、头部转动；质量按评审样例标准判断 |
| L05 | 标准模型包 | 下载文件完整，在确定版本的目标软件中实际加载通过 |
| L06 | 失败恢复 | 拆层、绑定、导出失败有具体反馈，可重试，上一份成功产物保留 |
| B01 | 模块隔离 | 项目 Agent 和画布不提供 Live2D 操作；动画资产更新不影响 Live2D 模型 |

## 11. 开发拆分与交付

两条功能线同期交付，按独立模块组织开发：

1. **动画资产与页面**：项目页面结构、我的资产、项目资产、引用与版本更新。
2. **项目 Agent**：页面上下文、内容操作、确认机制、生成任务与结果落位。
3. **动画制作**：结构化剧本、分镜、多角色带音频镜头生成。
4. **成片剪辑**：基础时间线、原声、背景音乐、字幕与导出。
5. **独立 Live2D**：资产库入口和列表、专用制作界面、拆层与绑定服务、预览与导出。
6. **联调验收**：动画流程、Live2D 流程分别验收，并检查模块边界。

建议先完成模型能力验证，同时开展页面和数据契约设计；确认服务输入输出后接入正式交互。任务存储等底层基础设施可以复用，但不得因此将 Live2D 纳入项目 Agent 或画布工作流。

## 12. 本期不做

- 工作室复杂成员权限、审核审批和多人实时协作。
- 专业级调色、复杂合成和高级剪辑特效。
- 独立 TTS、声音克隆及角色单独音轨生成。
- Live2D 精细绘图、网格和变形器编辑器。
- Live2D 与动画项目的资产引用、自动同步或 Agent 联动。
- Live2D 模型交易市场和公开分享社区。

## 13. 评审后需补齐的参数

以下参数不影响已确认的产品方向，但必须在开发排期及上线前落定：

- 视频模型选择、单镜头时长、成片最大时长与导出规格。
- 多角色、口型、音色和视觉一致性的验收样例及通过标准。
- PNG 文件大小、尺寸、画风及姿态支持范围。
- Live2D 目标软件版本、动作幅度范围和质量验收样例。
- 可编辑工程导出能力及对应的外部精修说明。
- 各类任务的耗时目标、并发限制、超时与重试规则。
- 背景音乐支持的导入格式、文件大小与时长限制。
- 第三方依赖授权与部署方案。

上述内容由产品与技术共同评审，不预设未经验证的性能或质量承诺。
